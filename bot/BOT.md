# BOT.md — 多 Agent 工作规范与通知板

> 版本：v1.0（2026-11-12）
> 适用对象：在本仓库工作的 AI 编码 agent（Claude Code、Codex、Copilot 等）
> 注意：本目录的 "agent" 指 AI 编码助手，**不是** NexusCore 内核运行时里的 Bot；同名不同物。
> 与 [AGENTS.md](../AGENTS.md) 的关系：AGENTS.md 是强制编码约束；本文件只定义协作与记忆协议。两者冲突时以 AGENTS.md 为准，并当次修正本文件。

## 1. 目录结构

```text
bot/
├── BOT.md              # 本文件：工作规范 + 通知板（谁在做什么）
├── Bots.md             # 项目共享记忆与进度（项目级事实唯一入口）
├── <agent-name>/       # 每个 agent 一个文件夹，只放个体记忆
│   └── memory.md
├── _template/          # 新 agent 的模板
│   └── memory.md
└── archive/            # 整理时归档的过期条目（按需创建）
```

## 2. 核心原则

1. **文件即通知，拉取式**：没有后台推送。任何 agent 开工前必须主动读 BOT.md 与 Bots.md；不读就开工视为流程违规。
2. **共享记忆单点**：项目事实只写 `Bots.md`；个人目录不得私藏项目级事实。
3. **个人记忆只放个体经验**：自己的偏好、踩坑、工作日志、未验证假设、交接事项。
4. **git 是事实层**：原始对话与改动以 commit 历史为准；不把 diff、大段日志复制进记忆。
5. **少即多**：`Bots.md` ≤ 200 行、个人 `memory.md` ≤ 100 行；没有未来复用价值的内容不记（显著性原则由 agent 自行判断，不硬编码"只记失败"之类的规则）。
6. **结论带证据**：每条记忆附验证证据（文件、命令、commit、测试结果）；猜测必须标 `[未验证]`。

## 3. 会话协议

### 3.1 开工（按序，必做）

1. 读 [AGENTS.md](../AGENTS.md)。
2. 读 [Bots.md](Bots.md)，了解项目记忆与当前进度。
3. 读 `bot/<自己>/memory.md`。
4. 读本文件 §4 通知板：若目标任务已被他人认领且未过期，不重复开工。
5. 在通知板追加一行认领（不要改动他人行）。

### 3.2 收工（必做）

1. 更新 `Bots.md`：进度日志追加一行；如有新的项目级事实，写入"项目记忆"。
2. 把本次新学到的个体经验写入 `bot/<自己>/memory.md`。
3. 把通知板中自己的行标记为 `done`，附 commit 或产出物。
4. 有未完成项时，留下交接条目（下一步做什么、卡在哪里）。

### 3.3 长任务心跳

预计超过 2 小时的任务，每完成一个可验证阶段就更新通知板自己那一行的时间与状态；`working` 超过 24 小时未更新视为 stale，可由后来者接管并在备注中说明。

## 5. 记忆写入规范

### 5.1 条目格式

```text
- YYYY-MM-DD [已验证] 事实 / 规则 —— 证据: <文件 / 命令 / commit>；适用: <场景>
- YYYY-MM-DD [未验证] 猜测 —— 需要: <验证方式>
- YYYY-MM-DD [过期] 旧结论 —— 被 <新结论 / 日期> 取代，原因: <原因>
```

### 5.2 规则

1. 相对时间一律归一为绝对日期（"昨天" → 具体日期）。
2. 结论必须附证据；没有证据的观察标 `[未验证]`，后续验证后升级并注明。
3. 被推翻的旧结论不静默删除：标 `[过期]` 并写明原因与替代条目。
4. 不写密钥、token、个人隐私；不复制大段代码与日志。
5. 一条记忆只表达一件事；合并重复条目，保留最强证据。

## 6. 并发与冲突

本仓库很少发生多个 agent 同时工作，因此**不引入锁服务、数据库或后台守护进程**，只保留轻协议：

1. 先读后写；写前重新读一次目标文件，确认没有他人更新。
2. 每次只追加或只改与自己相关的行 / 段落。
3. 同一文件出现 git 冲突时，保留双方内容并合并（union），由后写者整理，不强制覆盖。
4. 需要"抢占"某模块时，在通知板写明范围；冲突范围以先登记者为准。
5. 任何自动化"通知"都只是文件更新提醒；agent 不假定对方已读。

## 7. 整理（简化版 Auto Dream）

**触发**：每完成一个里程碑，或 `Bots.md` 超过 200 行。

**执行者**：当次最后一个收工的 agent（或人工）。

**四步**：

1. Orientation：通读 Bots.md、各 agent memory 与最近 commit，列出主题与缺口。
2. Signal Gathering：找出重复条目、互相矛盾的结论、过期信息、长期 `[未验证]` 假设。
3. Consolidation：合并重复；把已验证结论上移为项目事实；把只与个人相关的经验下移到个人目录；相对时间归一。
4. Pruning & Indexing：删除无复用价值条目，归档到 `bot/archive/`，把 Bots.md 压回 200 行以内。

**安全阀**：任何被推翻的结论都保留 `[过期]` 记录与原因，不物理删除证据链。

## 8. 记录边界

**记录**：架构决策及理由、环境 / 构建 / 运行中的非显然事实、踩坑与规避方法、验证过的结论、任务交接。

**不记录**：代码本身（看仓库）、一次性调试输出、可从代码或 git 直接得到的事实、密钥与个人信息、大段日志与堆栈。

## 9. 新增 agent

1. 复制 `_template/` 为 `bot/<agent-name>/`，agent 名用小写工具名（`claude` / `codex` / `copilot`）。
2. 在 §4 通知板登记一次即可，无需审批。
3. 新记忆先从 `[未验证]` 开始，验证后升级；禁止把项目级事实写进个人目录。
