## 1. 裁决

下列口径覆盖原始清单里写不开的句子。

1. **系统 Bot 只有四个保留名**：`user_bot`、`create_bot`、`monitor_bot`、`security_bot`。插件不得注册同名或 `create_` / `monitor_` / `security_` 前缀。
2. **每个 L2 插件都有 owner bot**（清单 `bot_templates[0]`）。它负责拉起和回收插件进程，经它做单次投递委托。工具插件、商场插件、设置插件同样要有 owner bot。「只有业务插件才注册 Bot」不成立。
3. **业务 Bot 是自然语言入口**，命名 `xxx_bot`。它可以和 owner bot 是同一个，也可以是插件另外注册的 Bot。用户 Bot 命名 `user_xxx_bot`，由用户经 Bot 工厂创建。
4. **中台助手使用自己的 `bot_id` 进总线**，不得冒用 `user_bot` 凭证。代批范围由用户显式授予：哪些 Bot、哪些 Tier 1 动作。插件安装与卸载、进程 Exec、密钥、放行沙箱网络仍由 `user_bot` 在真实交互终端批准。
5. **`plugin_type` 保持四值**：`ingress`、`workspace`、`executor`、`knowledge`。业务、工具、主题、Bot 模板是产品分类，写在清单的 `plugin_category`，不改内核 CHECK。
6. **配置中心仍只有 `plugin / bot / agent / global`**。工具定义、MCP、Skill 源码、Bot–工具授权、沙箱轨迹、插件商场目录不进配置中心，也不新增内核表。这些数据由对应插件自有存储持有。
7. **Agent 仍是探针，不是工具的一种**。主页单独展示，Bot 编辑页用单独下拉框选择绑定。工具授权表不收录 Agent。
8. **脑手分离不变**。Bot 不执行 Shell。联网限制做在 `agent-daemon` 的执行策略上。轨迹记录「已经发生的调用」，不代替网络隔离。

## 3. Bot

### R1 四类身份

系统能列出并区分：

| 身份 | 是谁 | 命名 |
| --- | --- | --- |
| 系统 Bot | 内核四角色 | 保留名，不可注册 |
| 插件 owner bot | 某个插件的进程宿主 | 由该插件清单声明，通常 `xxx_bot` |
| 业务 Bot | 把自然语言变成该插件的工具调用 | `xxx_bot`，可与 owner 相同 |
| 用户 Bot | 用户经 Bot 工厂创建 | `user_xxx_bot` |
| 中台助手 | 用户可选的调度助手 | 自有 `bot_id`，见 R20 |

验收：

- Bot 列表能看出身份，不靠展示名猜测。
- 保留名注册被拒绝。
- 用户 Bot 的 `MEMORY.md` 仍不得超过 200 行，保存后经重启生效。

### R13 基础功能的助手

五个基础插件各自提供一个已初始化的助手 Bot。用户在群聊或该插件页面用自然语言可以发起：

- 创建用户 Bot（进入 Bot 工厂校验，不绕过保留名和 200 行限制）
- 搜寻本机 Agent
- 搜索插件并发起下载提案
- 在已授权范围内管理 Skill 与 MCP 登记

助手发到总线上的仍是普通信封。创建、下载、安装、卸载不在助手进程内直接完成。

### R20 中台代批

用户可以授予中台助手：代替自己处理**哪些 Bot** 的**哪些 Tier 1 申请**。未出现在授予列表中的 Bot，助手不能代批。

| 级别 | 动作 | 结果 |
| --- | --- | --- |
| Tier 1 | 切换主题、切换语言、读取健康与 Bot 状态、邀请已存在的 Bot 入群、调用已授权的只读工具 | 助手以自己的身份提交；审计记录写明代批人与被代批的 Bot |
| Tier 2 | 插件安装、升级、卸载、进程 Exec、提取密钥、放宽沙箱网络 | 助手只能生成提案。批准人仍是 `user_bot`，且必须在交互终端确认 |

未识别的动作按 Tier 2 处理。授予关系存在中台助手所属插件的存储中，不写进 `kernel_config_*`。

## 4. 插件

### R2 产品分类

清单增加 `plugin_category`，取值：

| 分类 | 含义 | 进程 | Bot |
| --- | --- | --- | --- |
| `foundation` | 第 5 节五个基础功能 | 有 L2 则必须有 owner bot | owner bot，并可有助手 Bot |
| `business` | 完整业务领域 | 有 L2 | owner bot + 至少一个业务 Bot |
| `tool` | 系统工具、Skill、MCP、搜索 | 有 L2 | owner bot。不把工具本身注册成 Bot |
| `theme` | 只提供前端主题资源 | 无 L2 | 不注册 Bot |
| `bot_pack` | 只提供 Bot 蓝图模板 | 无 L2 | 不注册 Bot。用户选用模板后才创建 `user_xxx_bot` |

`plugin_type` 仍按插件在总线上的角色填写，与 `plugin_category` 独立。主题包、模板包不进入进程监管。

### R3 业务插件与依赖

一个业务插件可以在清单里依赖多个基础插件（群聊、工具、Agent 搜寻、Bot 工厂）。依赖深度不超过 2，有环拒绝加载。业务插件不内嵌这些基础插件的第二份二进制。

### R4 安装留底

安装、升级、停用、卸载每一次都留下内核记录，至少包含：插件 ID、清单摘要、动作、操作者 Bot、时间、结果。现有 `kernel_plugins` 状态与 `kernel_config_audit` 能表达的，继续用它们。记录只增不改。商场自己的目录日志不能代替这条内核记录。

失败的尝试同样留底，并写明拒绝原因（摘要不符、环路、深度超限、未获批准）。

### R5 五个基础功能

开箱可用，并在宿主左侧工坊中有自己的页面：

| 功能 | 插件 | 页面要完成的事 |
| --- | --- | --- |
| Agents | `plugin_agent_discovery` | 列出本机已发现的探针、版本与能力 |
| Bots | `plugin_bot_creator` | 创建与编辑用户 Bot，编辑记忆，选择绑定的 Agent |
| 工具 | `plugin_tool_center` | R6、R14、R16 |
| 插件商场 | `plugin_marketplace` | R7、R10 |
| 系统设置 | `plugin_settings` | R8、R19。此插件目前不存在，属于本需求的交付 |

五个页面都挂在宿主布局里，见 R18。

### R21 业务插件清单

下列插件只定义接入标准，不在本需求内实现功能：浏览器、VS Code、项目、图书馆、知识库、Wiki、剪映、视频、SSH、cc-switch。

接入标准：`plugin_category=business`，声明依赖的基础插件，带 owner bot 与业务 Bot，安装走 R10。商场可以展示它们的目录项，目录项不等于已安装。

**M18/M19 实现规格**（在 R21 接入标准之上）：见 [M18-业务插件需求规格.md](M18-业务插件需求规格.md)（`plugin_pm`、Ingress 仅 `user_bot`、`plugin_obsidian` 只读文件查询；**不含** `plugin_memory` 图谱能力）与 [M19-模型与执行路由.md](M19-模型与执行路由.md)（`plugin_model_router`，独立于 M18）。

## 5. 工具、沙箱与 Agent

### R6 工具中心

工具中心展示三类，并持久化在工具插件自己的存储中：

- 系统服务：Bot 可调用的内置能力
- Skill：可编辑的模板或脚本
- MCP：外部 MCP 服务的登记与连接信息，运行在探针侧

Bot 在自己已被授权的范围内，可以对 Skill 和 MCP 登记做增删改查。系统服务不允许改代码、不允许删除。

内核与配置中心不保存工具源码、MCP 连接串和 Skill 正文。密钥只用 `secret_ref`。

### R14 可编辑与不可编辑

每件工具有 `editable`。`editable=false` 的更新和删除被拒绝。`editable=true` 的修改留下版本记录，供回看。进程重启后分类与内容仍在。

### R16 记忆、授权与强绑

- Bot 编辑页可以查看和保存 `MEMORY.md`，超过 200 行拒绝保存。
- 同一页可以选择该 Bot 允许使用的工具。关系是多对多。
- 未授权调用被拒绝，并记入轨迹。
- 关键工具可以标记为强绑：只有清单中点名的 Bot 能获得授权，其余授予请求被拒绝。互联网搜索默认是强绑工具。

授权存于工具插件，不进配置中心。

### R9 沙箱

探针执行工具时：

- 默认没有任何出站网络。
- 仅当工具声明为互联网搜索，且该 Bot 持有该工具的授权时，允许 DNS 与 HTTPS。
- 其他工具即使在参数里写了 URL，也不能打开外联。
- 每次执行留下轨迹：Bot、工具、是否联网、入参摘要、退出码、耗时、蒸馏结果。原始大输出不进入 Bot 上下文。

轨迹存在工具插件或沙箱所属插件的存储中。Hub 只转发执行与投递通知，不把轨迹表放进 `kernel` schema。

### R11 搜索通知

搜索工具一旦实际发起外联，必须投递一条审计消息。接收者至少包括 `user_bot`。若用户打开了中台通知，同一条消息也投递给中台助手。消息写明发起 Bot、工具、目标域名。用户可以据此中止后续调用。

只在界面上显示一条手工写入的轨迹，不算满足本条。

### R12 Agent 的展示

- 工坊主页有独立的 agents 入口，不放进工具列表。
- Bot 编辑页有单独的下拉框，数据来自 Agent 搜寻结果，保存为该 Bot 的绑定探针。
- 未绑定的 Bot 不能把用户任务派到某个 CLI 探针。

### R15 下载与审批绑在一起

名为下载的能力只做一件事：取得制品、校验 SHA-256、做依赖环路和深度检查，然后生成安装提案。它不能把插件标成已安装，也不能拉起进程。安装与卸载只能从已通过 R10 的提案继续。

## 6. 商场、设置与审批

### R7 商场

商场助手可以用自然语言搜索目录，并展示：依赖哪些基础插件、依赖深度、是否有环、清单摘要是否匹配。用户确认后，商场只提交安装提案。

### R8 设置

设置插件提供一个助手，接受自然语言：

- 切换主题（R19）
- 切换界面语言
- 卸载某个插件

卸载走到 R10，设置助手不能自己卸载。语言切换只改变界面文案，不改变 `bot_id`、信封和日志字段的英文标识。

### R10 下载、安装、卸载

三步都要留下 R4 的记录。

1. **下载**：摘要校验、依赖图、环路、深度 ≤ 2。任一失败则停止，不进入安装。
2. **安装**：生成配置提案，`security_bot` 预审，`user_bot` 按 checksum 在交互终端批准，然后才激活并按拓扑加载。
3. **卸载**：仍被其他插件依赖时拒绝单点卸载。用户明确要求级联后，按逆拓扑先停 L2，再停 L1。

中台助手在这三步上的权限见 R20：只能提案，不能批准。

## 7. 界面

### R17 群聊成员

群聊房间可以扫描当前的用户 Bot 和业务 Bot，由用户勾选入群。未入群的 Bot 即使用户写了 `@`，也不投递任务。Bot 回复里的 `@` 仍然只作展示，不唤醒其他 Bot。

成员名单存在群聊插件自己的存储中。

### R18 插件 UI

插件页面是宿主布局中的一块视区：使用宿主的字体、颜色和间距。插件不实现第二套顶栏、第二套主题开关。主题包只替换宿主公布的主题变量。

### R19 三种主题

宿主提供跟随系统、白昼、黑夜。选择结果持久化在本机。设置助手发起的切换与用户点击开关效果相同。刷新页面后主题保持。

### R22 纪事

左侧纪事三项目前的跳转和徽章不能当作完成。

| 入口 | 行为 |
| --- | --- |
| 日志 | 打开可过滤的运行记录，并能从一条记录进入对应的沙箱轨迹 |
| 数据 | 按 Bot 浏览四层单体记忆：会话、笔记、表征、`MEMORY.md`。图谱在 `plugin_memory` 落地前不作为本条验收 |
| 定时任务 | 列出已启用的任务，至少包括 Auto Dream 与用户创建的巡检。可以启停，可以看上次执行结果 |

定时任务的触发不占用内核队列的业务语义；到点后仍以某个 Bot 的名义投递一条普通消息。

## 8. 验收时不算完成的现状

下列实现可以保留为演示，但不得记为 R20、R22 已通过：

- 代批网关只按动作名字返回允许，不核对助手身份和用户授予列表
- 纪事里「数据」「定时任务」的数字是固定文案

R6、R14、R16 已于 2026-11-19 关闭：工具分类、Skill 正文、MCP 的 `endpoint_ref` / `secret_ref` 和多对多授权在 `plugin_tool_center` 目录中，重启后仍在。不设 `-data` 的进程内存只作为 M10 回归，不能再当作这三条的实现。

R9、R11、R12 已于 2026-11-19 关闭：普通工具不能因参数中的 URL 出站；已授权搜索完成 DNS 与 HTTPS 后向 `user_bot` 投递审计；未绑定探针的 Bot 不能派发 CLI。

R7、R10、R15 已于 2026-11-19 关闭：`plugin_marketplace -data` 的下载只生成提案；安装仍由 `user_bot` 在交互终端按 checksum 批准；被依赖时单点卸载被拒绝。不带 `-data` 的内置目录只作为 M10 回归，不能再当作这三条的实现。

## 9. 非目标

- 不实现 R21 清单中的业务插件本身
- 不把 MCP / Skill 运行时放进 Hub 或配置中心
- 不新增 `kernel_tool_trajectories`、`kernel_bot_tool_grants`、`kernel_plugin_audit_logs`
- 不修改 `plugin_type` 的 CHECK
- 不让中台助手持有 `user_bot` 凭证
- 不在本需求中实现知识图谱与金库（仍属 `plugin_memory`）
