# NexusCore M4 里程碑开发与落地总结

## 1. 里程碑概述

**M4 里程碑（Vue 3 前端工作台与多 Bot 群聊实机演示）** 现已全面交付落地。
NexusCore 在继承 M1 微内核底座、M2 配置审批与插件运营、M3 单体记忆与群聊插件的基础上，正式建立了独立、解耦的现代前端可视化工作台（`Frontend/`），打通了从底层物理探针、微内核事件总线、独立群聊路由到浏览器图形界面的全链路闭环。

```

|  - 多 Bot 群聊视区 (MentionInput / ChatBubble / 流式 Markdown 渲染)               |

|  - Agent 执行监视面板 (AgentActivityCard / 帧级别流转 / 终端回显)               |
```

## 2. 微内核与网关核心改造

### 2.1 HTTP API 与 SSE 事件广播机制 (`hub/httpapi/`)
为支持前端实时响应系统状态，微内核网关 (`:7200`) 扩充了标准 REST API 与 SSE 事件流：

1. **CORS 预检与全量跨域支持**：
   - 支持 `OPTIONS`, `GET`, `POST`, `PUT`, `DELETE` 跨域预检与标准标头响应（`Access-Control-Allow-Origin: *`、`Access-Control-Allow-Headers`、`Access-Control-Allow-Methods`）。
2. **SSE 单向实时事件广播 (`GET /v1/events/stream`)**：
   - 内部维护并发安全的订阅者通道池（`sseSubs map[chan sseMessage]struct{}`）；
   - 支持非阻塞广播与慢客户端丢弃机制，防止单连接挂死拖累内核事件分发；
   - 广播三类核心事件：
     - `bot_status`：Bot 在线状态变迁（`idle` / `thinking` / `executing`）；
     - `chat_message`：房间群聊消息转发与持久化缓存；
     - `agent_event`：Agent 传输帧与执行状态事件。
3. **单体记忆管理与硬约束强校验 (`GET/PUT /v1/bots/{bot_id}/memory`)**：
   - 对接底层 `memory.Manager`；
   - 写入时严格执行 Claude Code 规范：**`MEMORY.md` 行数不得超过 200 行**，超过 200 行立即拦截并返回 `400 Bad Request`（错误信息明确返回当前行数与上限）。
4. **Bot 独立重启端点 (`POST /v1/bots/{bot_id}/restart`)**：
   - 允许工作台对指定 Bot 触发无缝重启以加载最新记忆或画像，无需重启 Hub 进程。
5. **群聊消息中继 (`GET/POST /v1/chat/messages`)**：
   - 暂存并回放群聊历史记录；
   - 接收前端用户发言并通过 SSE 广播至所有在线客户端与监听模块。

### 2.2 Supervisor 独立重启策略 (`hub/supervisor/`)
- 新增 `RestartBot(ctx, botID)` 方法：
  - 加锁进入互斥临界区，验证 Supervisor 未处于全局关闭状态；
  - 标记目标 Bot 进程 `stopping = true` 并发送 SIGTERM/优雅关闭；
  - 遵循架构规范回收 L2 插件孤儿进程（先插件、后 Bot）；
  - 清理旧进程退避计数（`backoff` 与 `failures` 计数归零）；
  - 重新调用 `startLocked` 校验制品摘要、签发凭证并 exec 拉起新代 Bot 进程。

### 2.3 传输路由帧流转监控 (`hub/transport/`)
- Transport `Router` 新增 `OnFrame func(FrameEvent)` 钩子回调；
- 在会话建立 (`open`)、双向帧转发 (`data_in` / `data_out`) 以及流关闭 (`close`) 时，自动计算执行耗时（`ElapsedMS`）并回传统一格式的 `FrameEvent`；
- 在 `hub/main.go` 中将 `Router.OnFrame` 与 `api.BroadcastAgentEvent` 绑定，实时流向 SSE 前端大屏。

### 2.4 gRPC 状态变迁联动 (`hub/grpcd/`)
- 在 Bot 注册（`Register`）、拉取任务（`StreamTasks`）以及确认任务（`AckTask`）处触发 `OnStatusChange` 回调；
- 状态由 `idle` 自动流转为 `thinking`，执行完成后恢复 `idle`，前端群聊界面的 Bot 头像标签实时同步。

## 3. 前端工作台工程设计 (`Frontend/`)

### 3.1 技术选型与分层结构
- **开发框架**：Vue 3 (Composition API, `<script setup lang="ts">`) + Vite 5 + TypeScript 5
- **状态管理**：Pinia 2 (模块化 Store：`useChatStore`, `useBotsStore`, `useAgentStore`)
- **组件库与样式**：Element Plus 2.6.x + Element Plus Icons
- **内容渲染**：`markdown-it` + `highlight.js`（支持代码块高亮与流式气泡渲染）

```
Frontend/src/
├── api/
│   ├── client.ts         # Axios/Fetch 基础包装与网关地址配置 (:7200)
│   ├── bots.ts           # Bot 列表、单体记忆读写、重启 API 契约
│   ├── chat.ts           # 房间聊天记录拉取与消息投递
│   └── events.ts         # SSE EventSource 连接与生命周期管理
├── stores/
│   ├── bots.ts           # Bot 实体缓存、实时状态追踪、当前激活 Bot
│   ├── chat.ts           # 消息历史列表、流式渲染追踪、未读状态
│   └── agent.ts          # Agent 活动日志、实时执行帧、耗时与终端输出
├── components/
│   ├── ChatBubble.vue        # 气泡组件 (区分 User/Bot/System、Markdown+代码高亮)
│   ├── MentionInput.vue      # 智能输入框 (@ 触发候选下拉列表、Tab/Enter 补全)
│   └── AgentActivityCard.vue # Agent 活动卡片 (帧流转折叠、状态徽章、终端回显)
└── views/
    ├── WorkbenchView.vue     # 三栏工作台主视区 (左导航/中会话/右监控)
    ├── ChatView.vue          # 多 Bot 群聊主窗口与顶部状态栏
    ├── BotDrawer.vue         # Bot 单体画像与 MEMORY.md 编辑抽屉 (200行计数校验)
    └── AgentMonitorView.vue  # Agent 实时执行帧流转大屏与历史追踪
```

### 3.2 核心交互设计

1. **严格防级联的 @Mention 机制**：
   - 交互仅限用户消息：输入 `@` 时呼出在线 Bot 候选菜单，键盘上下键选择、Enter/Tab 补全；
   - 只有用户（`user_bot`）发出的 `@bot_id` 会被路由至目标 Bot；
   - Bot 回复中引用的 `@bot_id` 在前端呈现为特殊样式的纯文本徽章，绝不作为触发事件回投，从前端到插件双重守卫杜绝 Bot 互 @ 引起的无限级联死循环。
2. **Claude Code 记忆管理抽屉**：
   - 打开指定 Bot 的抽屉，可查看 System Prompt、Persona、Profile；
   - 内置代码/Markdown 编辑器编辑 `MEMORY.md`，底部提供实时行数计数器（如 `180 / 200 行`）；
   - 超过 200 行时界面给出警告提示并禁用保存；
   - 点击“保存并重启”，先 PUT 更新记忆文件，随后 POST 触发 Bot 热重载，提示刷新成功。
3. **Agent 执行可视化监控卡片**：
   - 捕获来自内核 SSE 的 `agent_event` 帧数据；
   - 实时呈现执行生命周期状态：`running` (执行中) -> `completed` (已完成) / `error` (失败)；
   - 格式化终端输出（`terminal stdout/stderr`）与精确执行耗时（毫秒级）。

## 5. M5 阶段规划与接续指引

M4 的成功交付为后续里程碑打下了坚实的可视化与实时通信基础。下阶段为 **M5 Agent Mesh 实真**，核心工作聚焦在底层真实受控探针与设备互联：

### 5.1 M5 核心任务
1. **真实的 `agent-daemon` 物理探针**：
   - 建立真实设备环境的反向 TCP 长连接；
   - 15 秒心跳保活与超时断线重连；
   - 工具清单（Tool Manifest）向 Hub 动态注册。
2. **Bash 工具安全白名单与截断**：
   - 受控 Shell 命令执行白名单；
   - 执行超时控制与大文件/大输出安全截断保护。
3. **HITL 人机协同确认机制 (Human-in-the-Loop)**：
   - 引入 `agent.yield_confirm` 状态：当 Agent 遇到高风险操作（如删除、系统重启等）时，Job 进入 `suspended`；
   - 前端工作台已在 `AgentActivityCard` 与 `WorkbenchView` 预留确认挂点，届时可通过前端按钮或 CLI 进行人工审批恢复（`POST /v1/jobs/{id}/resume`）。
4. **流式终端回显冷热分离**：
   - 大体量原始输出落文件冷存储（`raw_stream_uri`）；
   - 提取结构化摘要流向前端大屏展示。

### 5.2 开发者下次启动提示
- **日常单测与语法检查**：`make test` 与 `make vet`
- **前端本地独立开发**：`cd Frontend && npm run dev`
- **全栈实机一键拉起**：`make launch-m4`
- **全链路冒烟验证**：`make smoke-m4`
