## 1. 单人开发原则

以下原则决定排期顺序，与功能优先级同等重要：

1. **竖切优先**：每个里程碑都以"跑通一条可演示链路"收尾，不做横向铺开。宁可少表少插件，也要先有端到端行为。
2. **CLI 先于 UI**：所有管理动作（建 Bot、授权、DLQ 运营、HITL 确认）先做命令行，Tauri 工作台推到 M7。CLI 就是 MVP 的第一个用户界面。
3. **内核先纯净，插件后复杂**：M1 内核 MVP 不含任何记忆代码与表；`bot-runtime`、`agent-daemon` 是架构强制独立进程，`plugin_memory` 按插件模型（M2 起）独立部署。记忆插件是第一个复杂插件，排在插件生命周期之后。
4. **契约先行的最小集**：proto / schema 先改文件再写代码；两个生成物（protobuf、migrate SQL）进仓库。
5. **测试预算固定**：每个模块 20-30% 的时间给表驱动状态机测试、契约测试与失败注入；不做 UI 自动化，冒烟脚本代替。
6. **改动受验收清单约束**：每个里程碑的完成定义绑定文档里已有的验收问题，不新增临时标准。

## 3. 里程碑详单

### M0 工程准备（4-5 人日）

1. 仓库目录：`hub/ bot-runtime/ agent-daemon/ cli/ proto/ migrations/ internal/ plugins/`。
2. 自带迁移 CLI `cmd/migrate`（up / down / probe，`_migrations` 记录表），应用 `database/sql + pgx/v5/stdlib`，不依赖 golang-migrate 二进制；内核迁移目录 `migrations/kernel`，插件迁移目录 `migrations/plugins/<plugin_id>/{schema...}`（DDL 留待 M1 与 M3 填入）。
3. PostgreSQL 连接与角色：database `nexus`；`NEXUS_PG_KERNEL_DSN`（hub）、`NEXUS_PG_MIGRATE_DSN`（可选，迁移）、`NEXUS_PG_MEMORY_DSN` / `NEXUS_PG_VAULT_DSN`（M3 起仅插件）；迁移 CLI 用 `to_regclass` 按当前 schema 探活。
4. proto 契约文件 + buf 配置（`buf` 未装时 `make proto` 打印安装提示）。
5. Makefile：`build / build-plugins / test / vet / lint / proto / migrate-probe / migrate-up / migrate-down / smoke-empty / clean`；docker-compose 按用户决策推迟到 M2。
6. D-22 / D-23 骨架：`plugin_memory` 目录与 manifest 占位；`kernel_config_documents / kernel_config_audit / kernel_secret_refs` 表骨架；内核二进制不引用任何记忆包。

验收（2026-11-13 重估后）：`go mod tidy + build + vet + test` 全绿（migrate 目录解析含配对冲突用例、Probe 按 `current_schema` 统计）；`make build` 产出 hub / bot-runtime / agent-daemon / cli / migrate 五个内核二进制，`make build-plugins` 产出 `plugin_memory`（占位）；`bin/hub -version` 打印版本；`cmd/migrate` 缺参正确报错。真库冒烟在配置 `NEXUS_PG_KERNEL_DSN` 后补跑 `make migrate-probe`。

### M1 内核 MVP（20-27 人日，核心）

按内核 MVP 详设第 3 节的模块顺序实现，每两三天收一次可见行为：

周 1：PG store + registry + config 最小集 + ingress（约 9 人日）

1. `migrations/kernel` 全量 DDL（queue / bot / plugin / ingress / outbox / payload / config 表；PG 类型与 CHECK）。
2. 凭证签发 / 校验 / 吊销；授权表；订阅登记。
3. 配置中心最小集：active 投影、`Get` + 读取 ACL、种子配置（`echo_bot` v1 / global 默认）、`kernel.config.changed`。
4. `IngressEnvelope` 校验器，失败注入五例：缺因果头 / 路径断裂 / 深度 32 / 根不一致 / 重复幂等键。

周 2：scheduler + outbox + eventbus（约 9 人日）

1. PG 队列：`SKIP LOCKED` 认领、`UPDATE ... RETURNING`、租约 60s + Heartbeat 10s 续租、`pg_notify` 唤醒 + 5-10s 兜底轮询。
2. D-04 四语义完整落地：`idempotency_key` UNIQUE、`suspended` 状态、人工确认幂等 CLI（`resume-list / resume-confirm`，continue / replay / discard 三选一）。
3. `kernel_job_intents` 副作用清单；毒丸 N=5 熔断；严格分区 advisory lock。
4. Outbox 扫描 → event.deliver job；dedup 幂等。

周 3：grpcd + supervisor + bot-runtime + transport（约 7 人日）

1. mTLS 或回环 trust；lease_token 与 AckTask 绑定防双 worker；`config_version` 上报。
2. 懒加载 exec + `binary_digest` 校验 + `idle_ttl` 退出 + 退避重启；`echo_bot` 测试夹具。
3. 反向 TCP + `transport_frame` 校验 + 心跳；loopback agent。

周 4：冒烟与恢复演练（约 3 人日）

1. 冒烟九步脚本化；hub 暴露 `/metrics`（队列深度、重试率、DLQ 率、Bot 启动延迟、租约过期率、Outbox 分发延迟、配置漂移数）。
2. 演练 hub 崩溃恢复；PG 角色边界验证（hub 无任何插件 schema USAGE）；NOTIFY 丢失下的兜底轮询验证。

退出条件：内核 MVP 详设第 8 节全部通过。**本里程碑不写任何记忆代码、不建任何记忆表；MCP / Skill 不出现。**

验收（2026-11-13 完成）：详设第 8 节六条全过，逐条证据见详设 §10.2。`make test-pg`（真库、`-count=1`）全绿，`go vet ./...` 无警告；`make smoke-m1` 九步链路 + 边界验收 + 兜底轮询通过；`make drill-crash-m1` 以真实 SIGKILL 注入 hub 崩溃、Bot 进程失联、LISTEN 专用连接强断，三者均恢复且无重复副作用，审计表对运行角色 append-only 边界成立。失败注入五例（缺因果头 / 路径断裂 / 深度 32 / 根不一致 / 重复幂等键）在 `hub/ingress` 固化。实现偏离（HTTP 入口适配器不改 proto 契约、`bots` 与 `bot_manifest` 职责切分、`kernel_plugin_subs.plugin_id` 可空、租约过期判定口径、`event.deliver` 不补造 `causal_path`、流式订阅 ack 脱离流上下文、buf 生成路径、每包独立测试 database）已回写详设 §10.1。未写任何记忆代码、未建任何记忆表；MCP / Skill 未出现。

### M3 Kernel单体记忆 + 插件安装规范 + GroupChatPlugin独立开发（10-12 人日）

> **战略转向**：将研发重心从前期理论化图谱晋升转向立即可用的“群聊协作智能体”，内核内置 Claude Code 式高效单体记忆，业务层通过独立插件解耦。

1. **插件安装规范完善**：
   - 制定标准独立插件目录规范（`GroupChatPlugin/` 示例模板：manifest.json, binary, migrations, config_schema）；
   - Manifest Schema 强约束：强制声明 `binary_path` 与 `binary_digest`（SHA256 强校验），静态声明 `subscribing / publishing / providing_tools / requiring_tools / bot_templates`；
   - 闭环安装生命周期：`install → security_review → user_approve → activate`，卸载严格遵守“先插件进程（L2）、后 Bot 进程（L1）”。
2. **Bot 单体记忆系统（默认内置 Kernel/）**：
   - 深度对齐 Claude Code 四层文件系统记忆栈：
     - **Transcripts（原始会话层）**：`data/bots/<bot_id>/memory/transcripts/<session>.jsonl`，Append-Only，事实溯源底座；
     - **Memory Notes（离散笔记层）**：任务中自主捕获显著性（Salience）经验、踩坑记录与非标参数；
     - **Memory Representations（结构化表征层）**：离线合成的主题 Wiki 与结构化参考文档；
     - **Injected Context（常驻注入层）**：每次会话启动预加载的极小切片（`MEMORY.md`），**铁律约束严格 ≤ 200 行（约 500~2000 Tokens）**，配合 Prompt Caching 确保 85%~93% 缓存命中，彻底消除 Token 二次方复合膨胀。
   - **Auto Dream 离线整合**：Kernel 异步四阶段流转（Orientation → Signal Gathering → Consolidation → Pruning & Indexing）；
   - **重启策略（Restart Policy）**：人格、系统提示词、画像与单体记忆更新采用**进程重启**直接生效，零复杂运行时热更状态机负担。
3. **GroupChatPlugin 独立开发（放置在 GroupChatPlugin/ 独立目录）**：
   - 独立开发、独立编译为 L2 插件二进制；
   - 房间与消息时序管理、群聊上下文滑动窗口；
   - **严格限制“仅仅用户@触发”**：只有人类用户消息显式 `@<bot_id>` 时激活对应 Bot；Bot 回复中的 @ 仅作纯文本展示，**禁止 Bot 间自发级联互 @ 唤醒**，杜绝死循环与发散 Token 膨胀。
4. **Bot 角色定位更新：简单 Agent（Simple Agent）**：
   - 每一个 Bot 都是轻量简单 Agent，只能使用系统提供的各种功能与工具；
   - **禁止长时间思考**：单次推理超时硬封顶（10~15 秒），禁止深度递归 CoT 循环；
   - **禁止直接执行 Shell**：Bot 自身无任何系统 Shell 执行权限，所有物理与环境操作必须经 Hub Transport 路由（反向 TCP）调度至受控的 `agent-daemon` 执行。

验收（2026-11-13 完成）：
- `GroupChatPlugin` 通过标准插件安装、审查与激活闭环；
- 集成自动化测试下（`make smoke-m3` 九步全链路通过）：模拟用户发消息 `@ops_bot`，Bot 挂载自身四层单体记忆唤醒，调用 `loopback_agent` 执行受控检查并在群内汇总结构化回复；未被 @ 的 `qa_bot` 保持静默（任务数为 0）；Bot 回复中含 `@qa_bot` 文本时被 GroupChatPlugin 识别为展示属性，绝不触发下游任务投递，彻底杜绝级联死循环；
- Auto Dream 四阶段离线整合顺利完成，结构化主题表征 Wiki 自动生成，`MEMORY.md` 压平重构且严格保持 ≤ 200 行约束；
- `make test`、`make vet`、`make smoke-m1`、`make smoke-m2`、`make smoke-m3`、`make drill-crash-m1` 全部持续全绿。

### M4 Frontend (Vue 3) 工作台与多 Bot 群聊实机演示（12-14 人日）

### M8 基础模块沉淀与无头化接口（8-10 人日，已完成）

> **战略重点**：将多 Bot 群聊（GroupChat）、Agent 探针网格（Agent Mesh）与 Bot 创建工厂（Bot Creator）彻底解耦，**下沉沉淀为无头（Headless）基础模块服务**。模块自身**绝不负责任何 UI 渲染**，并在配置中心注册接口契约与 SemVer 版本标识。业务插件清单面向接口声明依赖，内核按 DAG 拓扑排序按序加载；内置循环依赖检测、依赖层级限制（Max Depth ≤ 2）、逆序安全卸载与平滑热更治理。详见专项详设 [milestones/M8-基础模块与依赖治理.md](milestones/M8-基础模块与依赖治理.md)（第 1–6 节为无头模块，第 7 节起为依赖治理）。

2. **插件能力注册与依赖生命周期治理**：
   - **接口注册入配置中心**：基础模块在 `scope_type='plugin'`、`config_key='interfaces'` 下注册提供的能力契约与 SemVer 版本标识，内核动态生成全局接口提供者索引；

   - **反向依赖安全卸载**：被依赖模块默认拒绝单点卸载，仅在显式 `--cascade` 下按逆拓扑序由上至下受控停机；
   - **两阶段平滑热更新**：兼容版本采用蓝绿滚动拉起、探活成功后原子切流并排空停用旧进程。

### M9 全局 UI 原型、标准群聊与沙盒工具轨迹审计（10-12 人日，v0.1.0 旗舰定版）

> **详设依据**：参见专项详设文档 [milestones/M9-标准群聊与全局UI.md](milestones/M9-标准群聊与全局UI.md) 与 [milestones/系统Update-全局UI与沙盒轨迹.md](milestones/系统Update-全局UI与沙盒轨迹.md)

1. **全局统一工作台 UI 原型落地（Atelier Code 架构）**：

     - 上半区（纪事 Chronicles）：**日志**（点击直接滑出内置沙盒工具使用轨迹抽屉）、**数据**（四层单体记忆库与图谱）、**定时任务**（自动巡检与 Auto Dream 离线流转）；

2. **内置沙盒工具使用轨迹记录体系（Tool Trajectory Sandboxing）**：
   - **核心定位澄清**：沙盒不仅用于执行隔离，更作为**全量捕获并审计 Bots 工具调用轨迹的受控留痕中心**；
   - **脑手分离**：Bot 自身永远禁物理 Shell，物理操作交由 `agent-daemon` 在沙盒内执行；
   - **全量轨迹落盘（`kernel_tool_trajectories`）**：捕获 `bot_id`、`tool_id`、完整参数 JSON、终端原始输出引用、退出码与毫秒级耗时，作为单体记忆溯源与因果链审计依据；
   - **网络沙盒分级策略**：普通执行工具默认 `network=none`（彻底离线）；互联网搜索工具仅白名单放行 443/53 端口，且**强制触发 Ingress 审计事件通知用户/中台 Bot**；
   - **可视化抽屉**：点击“日志”或输入框下方的 `[⚡ 沙盒工具轨迹]`，即刻滑出查看实时轨迹流水。
3. **标准群聊插件微前端自治与独立持久化**：
   - 生产级多 Bot 群聊协同：话题流转、Markdown 打字机流式渲染、内嵌终端执行折叠卡片；
   - 成员动态扫描与自由勾选：群聊视区内动态扫描系统 Bot、用户自建 Bot 与业务插件 Bot，自由选择入群；
   - PostgreSQL 独立 `groupchat` schema 全量持久化（开辟独立空间，内核不交叉越权读取）；
   - **防死循环安全铁律（代码级三层锁）**：单向唤醒门（仅限 `sender_role == 'user'` 解析 @ 唤醒）、Bot 回复纯展示降级（Bot 回复中的 @ 严禁投递总线任务），杜绝 Token 爆炸。
4. **两级进程模型生命周期**：
   - L1 Owner Bot `groupchat_bot` 由 Supervisor 拉起；L2 插件服务二进制由 Owner Bot 以独立进程组（`setsid`）自治 exec 拉起，提供 `:7300` 服务；

### M10 工具中心、MCP/Skill 插件化治理与中台 Bot 审批闭环（12-14 人日，v0.2.0 已完成）

> **详设依据**：参见专项详设文档 [milestones/M10-工具中心与代批.md](milestones/M10-工具中心与代批.md)  
> **战略重点**：落实全局 Update 规划中的工具体系、生态闭环与中台代批安全防线。沉淀独立工具插件，支持 MCP / Skill 治理；建立三层 Bot 体系与中台 Bot 代理审批 RBAC；打通插件下载、安装、卸载三阶段安全审批闭环；为典型业务插件生态（浏览器、VSCode、项目、Wiki、剪映、SSH、cc-switch）提供统一接入底座。

1. **工具分类治理与独立工具插件（`plugin_tool_center`）**：
   - **工具分级**：可编辑工具（用户/插件自定义脚本、Prompt 模板）与不可编辑工具（系统底层驱动、探针 CLI）；
   - **MCP / Skill 边界隔离**：**微内核不存 MCP/Skill 代码与运行时**，代码存储、生命周期与环境拉起由独立工具插件自治管理，内核仅维系最简抽象元数据；
   - **Bot-Tool 授权矩阵**：配置中心建立 `bot_tool_grants` 多对多授权映射，支持特殊 Bot 与关键特权工具强绑。
2. **三层 Bot 体系与中台 Bot 代批授权安全防线**：
   - 规范确立系统 Bot、中台 Bot、用户自建 Bot（`user_xxx_bot`）与业务插件 Bot；
   - **中台 Bot（Hub Bot）**：以 `user_bot` 委派身份入总线代理调度；
   - **分级代批授权体系（Delegation RBAC）**：
     - **允许受控代批（Tier 1）**：UI 主题切换、非破坏性参数读取、低危通知中继、已预审白名单工具调度；
     - **严禁代批铁律（Tier 2 - Mandatory HITL）**：**插件安装卸载、二进制进程 Exec、敏感凭证提取、穿透沙箱网络规则**。此类请求无论中台 Bot 如何配置，必须由人类用户在交互终端或界面显式确认，严防 Prompt 注入渗透。
3. **插件商场与三阶段安全审批流闭环**：
   - 插件商场助手 Bot，支持自然语言检索插件、依赖深度与风险提示；
   - **下载阶段**：校验 SHA-256 Digest，依赖 DAG 构建，静态校验循环依赖（三色标记 DFS）与依赖深度（`MaxDepth ≤ 2`）；
   - **安装阶段**：生成标准配置提案（Proposal），经 `security_bot` 预审与 `user_bot` 交互审批后激活；
   - **卸载阶段**：反向依赖保护拒绝单点卸载，显式 `--cascade` 下按逆拓扑序由上至下受控停机。
4. **典型业务插件生态矩阵接入标准**：
   - 统一浏览器插件、VSCode 插件、项目管理（PM）、图书/知识库、Wiki、剪映视频、SSH、cc-switch 插件的标准接入规范。
